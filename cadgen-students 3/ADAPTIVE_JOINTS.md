# Адаптивные крепления для фиксированной декомпозиции

Новая логика работает на втором этапе. `decomposition.py`, `section_analysis.py`,
геометрические объединения и сохранённые 86 компонентов не менялись.
CADGen не запускается при сравнении: читаются STEP из `two_stage_final`.

## Геометрия крепления

`cadgen/adaptive_joints.py` исследует отдельные плоские участки настоящего B-Rep
стыка, обе роли донора/приёмника и несколько направлений профиля в плоскости
контакта. Оси прямолинейных границ дополняют две ортогональные ориентации.
Нормаль результата пересечения граней явно ориентируется наружу первой детали:
ядро может вернуть противоположную ориентацию независимо от исходных нормалей.

Кандидаты положений строятся сетками по ограниченной поверхности и центрами
треугольников её разбиения. Принадлежность проверяется по точной грани, расстояние
до внешнего контура и всех внутренних отверстий — по её проводам B-Rep.
Лучшие внутренние точки распределяются по стыку. Затем луч пересекает реальный
Solid и измеряет ближайший выход из материала с каждой стороны контакта.
Ограничивающий параллелепипед не служит доказательством наличия материала.

Начальная ширина, длина и глубина зависят от расстояния до границ и доступного
материала. Если конструкция не проходит проверки, пробуются масштабы **1, 0,5,
0,2 и 0,08**. Масштабируется только проектируемое крепление, исходные компоненты
не масштабируются. Используются существующие `sample_profile` и `profile_prism`:
`rectangular`, `v`, `trapezoid`, `dovetail`, `t`, `round`. Их определения не изменены.

В адаптивном поиске `min_wall=2` больше не задаёт минимальный размер паза и
обязательную оболочку толщиной 2 мм. Вокруг центрального зацепления проверяется
реальная оболочка, пропорциональная размеру выбранного профиля, и наличие
материала для основания выступа. Полученные компоненты обязаны оставаться
валидными единичными Solid. У открытых скользящих профилей дополнительно
проверяется путь всего компонента, а не только движение условного профиля.
Глобальная минимальная толщина стенок и механическая прочность не сертифицируются.

Зазор — верхняя граница пользовательского `clearance`, автоматически уменьшаемая
до 4% локального размера сопряжения: `min(clearance, 0.04 * size)`.
Нулевой зазор сохраняется; отрицательный или `>=1 мм` запрещён.
Проверяются реальные нормальные расстояния поверхностей построенного профиля.
Допуск объёмных операций ограничен объёмами локальных компонентов и размером
крепления, чтобы общий допуск больших деталей не скрывал ошибки маленького паза.

`min_part_fraction` не применяется к адаптивным пазам и болтам: маленькая деталь
не сравнивается с объёмом всей пары. Сохраняются проверки материала вокруг
крепления, связности Solid, отсутствия пересечений и изменения исходной формы
за пределами объявленного технологического зазора. Исходные отверстия не
заполняются: выступ переносится только из реального материала соседней детали.

Пазы имеют приоритет. Если на стыке не найден проверенный паз, пробуются
пропорциональные гладкие болты, гайки и отверстия меньших диаметров. Для них
проверяются полная колонна материала, опорные площадки головки/гайки, соосность,
пересечения и отдельные пути установки. `Bolty.build_bolt(..., adaptive=True)`
разрешает пропорциональную головку вместо обязательной прибавки 4 мм;
`Gaiki.build_nut(..., adaptive=True)` использует пропорциональный контрольный щуп.
Стандартные независимые генераторы болтов/гаек сохраняют прежние параметры.
Настоящая резьба не строится.

## Бюджеты и проверка сборки

На одну контактную пару предусмотрены максимум 384 конструкции, из них до 300
на пазы, с резервом для болтов. Бюджет распределяется между участками, ролями,
ориентациями и профилями. Возвращается до 12 представительных вариантов с
разными направлениями извлечения, затем альтернативами профиля.
JSON содержит параметры отказов, исследованные профили, число попыток и факт
ограниченности поиска. Ненайденное соединение не объявляется невозможным.

Существующая проверка полной сборки сохраняется: граф всех компонентов,
совместимость выбранных креплений, материализация всех изменений, пересечения
всех деталей, допустимые технологические пустоты и полная обратная
последовательность разборки. Неудача этого этапа не меняет декомпозицию.
Дискретные положения траектории не доказывают непрерывную бесстолкновительность;
механическое удержание и изготовимость не проверяются.

Старый подбор доступен как `propose_joints(..., adaptive=False)`; независимый
двухкомпонентный генератор и явный режим `combined` сохраняют прежние построители.
Автоматический второй этап по умолчанию использует адаптивные пазы/болты.

## Запуск без повторной декомпозиции

Из каталога `cadgen-students 3/`, в окружении с CadQuery:

```bash
python test/compare_adaptive_joints.py \
  --source generations/assemblies/two_stage_final \
  --output generations/assemblies/adaptive_joints
```

Сначала анализируется модель №3, затем остальные девять. Существующий каталог
результатов не перезаписывается. Для отдельной проверки: `--models 3` и новый
`--output`.

Для каждой пары с локально проверенным креплением сохраняются
`model_XX/pair_candidates/part_A__part_B/pair.step`, `pair.stl` и метаданные.
**Локальный успех не означает успех сборки всей модели.** Итог и причины —
`model_XX/assembly_report.json`. Только для полностью проверенной сборки создаётся
`model_XX/assembly/` с существующим экспортом STEP/STL и порядком сборки.

Сохранённые `two_stage_final`, `examples/assemblies` и
`examples/two_stage_decomposition` защищены проверкой контрольных сумм.

Автоматические тесты:

```bash
python -m unittest discover -s test -p 'test_*.py' -v
```

Сохранённые исходные STEP и все 86 геометрических компонентов использованы без повторной декомпозиции. Порядок обхода начинался с модели №3.

Итого: **104 контактные пары с допустимыми пазовыми вариантами**, **76 установленных пазовых соединений**, **10 проверенных сборок**. На каждой модели выбрано дерево соединений; все альтернативные стыки одновременно не оснащаются.

Болты на этих моделях не понадобились. Их резервный подбор проверен отдельным тестом, включая болт диаметром **0,4 мм** с совместимой гайкой и проверкой установки.

Результаты находятся отдельно: `generations/assemblies/adaptive_joints_final/`. В его `README.md` — ссылки на STL/STEP каждой сборки; `statistics.json` содержит диапазоны и подробную статистику отказов. Пример модели №3: `model_03/assembly/assembly.stl`, `assembly.step`, `parts_exploded.stl`.

Диапазоны **фактически установленных** креплений, мм:

| Параметр | Минимум | Максимум |
|---|---:|---:|
| Ширина входа профиля | 1.661236039e-05 | 26.7397418 |
| Глубина | 1.129411765e-05 | 13.3698709 |
| Центральная длина зацепления | 2.352941176e-05 | 68.80656594 |
| Зазор | 4.517647059e-07 | 0.2 |

Это наблюдённый диапазон на конкретных моделях, а не гарантированный диапазон для любой геометрии. Микроскопические стыки исходных компонентов приводят к микроскопическим креплениям и зазорам. Проверка CAD не подтверждает их изготовимость или прочность; для производства нужна отдельная политика допуска. Для точной геометрии следует использовать STEP: STL имеет ограниченную точность координат.

В локальном поиске выполнено 4417 попыток, отклонено 1627 вариантов. Не осталось контактных пар без локально допустимого паза в рамках этого поиска. Отказы отдельных конструкций включали недостаток материала, потерю/невалидность микроскопического тела при Boolean-операции, изменение формы вне заявленной пустоты и заблокированный путь. Точные размеры и причины сохранены в отчётах каждой пары.

**Проверки:** 80 автоматических тестов прошли; дополнительно повторно прошли 20 тестов прежнего генератора после сохранения его прежнего порядка выбора диаметров. Два прежних отрицательных сценария (узкая перемычка и произвольный поворот) теперь проверяют успешную адаптивную сборку. Прежнее ранжирование профилей/болтов тестируется с `adaptive=False`.

Все десять экспортированных сборок независимо проверены повторным чтением STEP/STL, восстановлением рецептов креплений, проверкой последовательности и сохранности каждого исходного геометрического компонента. Для адаптивных выступов проверена сохранность после STEP с их локальными объёмными допусками. `validation.json` содержит результаты. Контрольные суммы всех исходных результатов и 406 опубликованных файлов примеров совпали. На этапе реализации алгоритма commit и push не выполнялись.

Повторить независимую проверку сохранённых файлов без генерации:

```bash
python test/validate_adaptive_joints.py \
  --folder generations/assemblies/adaptive_joints_final
```

При переносе результатов в другой каталог исходников укажите
`--source generations/assemblies/two_stage_final`.

Изменённые файлы: `cadgen/assembly_geometry.py`, `cadgen/joint_design.py`,
`cadgen/decomposition_assembly.py`, `Bolty.py`, `Gaiki.py`,
`test/test_auto_decomposition.py`, `test/validate_auto_examples.py`,
`README.md`, `AUTO_DECOMPOSITION.md`.
Новые: `cadgen/adaptive_joints.py`, `test/test_adaptive_joints.py`,
