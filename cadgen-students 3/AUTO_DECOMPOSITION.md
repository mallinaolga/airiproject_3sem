# Автоматическая декомпозиция AIRI

Новый режим развивает двухкомпонентный генератор из коммита `27ff3e38`.
Исходные `cadgen/cad.py`, `sketch.py`, `extrude.py`, определения шести профилей,
`Bolty.py`, `Gaiki.py` и `Otverstiya.py` в этой доработке не изменены.
По умолчанию CLI по-прежнему использует прежний двухкомпонентный режим.

## Запуск

Из `cadgen-students 3`, в окружении с зависимостями проекта:

```bash
python -m cadgen.assembly_generator --count 10 --decomposition auto --connection auto --seed 42
```

Полный демонстрационный прогон с сохранением первых десяти успешных результатов
для GitHub (оба каталога должны быть новыми):

```bash
python -m cadgen.assembly_generator --count 10 --decomposition auto --connection auto --seed 42 --max-attempts 16 --output generations/assemblies/auto_seed42 --examples examples/assemblies
```

`--count` означает число запрошенных **успешных сборок**. Неудачные исходники,
разрезы и экспорты не засчитываются. При исчерпании попыток CLI возвращает 1,
манифест сохраняет фактический результат `incomplete`. Готовая серия возвращает 0,
ошибка аргументов — 2. Существующие каталоги не перезаписываются.

Прежние команды сохранены:

```bash
python -m cadgen.assembly_generator --count 1 --connection groove --seed 42
python -m cadgen.assembly_generator --count 1 --connection bolted --seed 42
python -m cadgen.assembly_generator --count 10 --connection random --seed 42
```

В автоматическом режиме можно явно ограничить семейство креплений:
`--connection groove`, `bolted` или `combined`, а также выбрать один из шести
`--profile`. По умолчанию для `--decomposition auto` оба параметра равны `auto`.
Случайный выбор типа крепления в этом режиме не используется.

## Исходная модель

Используется существующий `CADFactory`, а не новый генератор коробок.
Автоматический режим запрашивает 5–8 операций: первую ступенчатую
`TwoExtrudesFactory` на простом процедурном эскизе и следующие
`ExtrudeFactory` на случайных эскизах CADGen. Размер мира — 180–240 мм.
CADGen может отклонить отдельные операции: фактическое число и вся история
строительства сохраняются в `source`, программа — в `original.py`.
Неудачные исходники с несколькими Solid, невалидным B-Rep или нулевым объёмом
отклоняются. Для следующей попытки используется другой воспроизводимый seed.

Доступен `--cad-config` с существующей локальной Python-конфигурацией CADGen.
Подходящая декомпозиция для любой произвольной конфигурации не гарантируется.
`--source box` остаётся отладочным вариантом; экспорт демонстрационной серии
через `--examples` требует именно `--source cadgen`.

## Геометрические кандидаты и оценка

`cadgen/decomposition.py` рассматривает три доминирующих семейства нормалей
плоских граней; при недостатке плоскостей используются оси тензора инерции.
Для каждого направления анализируются реальные B-Rep-сечения:

- девять опорных уровней площади сечения;
- положения внутренних плоских граней, параллельных предполагаемому разрезу;
- сечения непосредственно по обе стороны такого перехода;
- середины исследованных интервалов для обнаружения узких перемычек.

Уровень естественного перехода сохраняется с исходной CAD-точностью. Его
округление до нескольких десятичных знаков могло бы создать тонкую платформу
вместо точного отделения геометрического элемента.

Площадь стыка измеряется пересечением **ограниченных граней** двух половин.
Общий объём Solid при касании равен нулю и не используется как площадь стыка.

Для пригодных разрезов вычисляются:

```text
score = 2 * neck_contrast
      + 2 * area_transition
      + 3 * simplicity_gain
      - 0.35 * volume_imbalance
```

`neck_contrast` сравнивает площадь стыка с более широкими сечениями с обеих
сторон; `area_transition` оценивает скачок площади; `simplicity_gain` —
уменьшение максимального числа B-Rep-граней дочерней детали относительно
родительской. Это интерпретируемая эвристика, а не сертификат геометрической
простоты. Принятие требует достаточного score, упрощения либо выраженной
перемычки и пригодности частей для креплений. Обычный параллелепипед не
разрезается лишь ради получения двух частей.

После каждого разреза проверяются отдельные валидные Solid, достаточный объём,
размеры и отсутствие пересечений. Объединение всех **немодифицированных**
компонентов должно восстанавливать исходник в пределах CAD-допуска.
Прямоугольники используются для защитных зон и раскладки, но не как
доказательство совместимости или сохранения исходной формы.

## Рекурсия и остановка

Для каждого компонента выбирается лучший выполнимый разрез, затем анализируются
оба дочерних компонента. Перед принятием строится пробное крепление и проверяется
вся текущая конструкция. При неудаче пробуются другие позиции, профили, типы
соединения и кандидаты разреза. Защищённые области уже принятых соединений
не могут быть разрушены новым разрезом.

Если прежнее крепление блокирует полезный разрез, алгоритм пытается заменить
его уже проверенной альтернативой того же родительского стыка. После
переразмещения заново проверяются граф, геометрия всех деталей и сборка;
ранее заблокированные соседи могут быть рассмотрены повторно.

После получения листьев варианты креплений дополнительно оцениваются на
фактической паре конечных соседей. Площадка под болт может быть доступна у
этой пары, даже если её не было у большой промежуточной подсборки. Замена
принимается только при улучшении оценки и успешной повторной проверке всей
геометрии и порядка. Принятые замены записаны в `checks.joint_refinements`.

Целевого количества деталей нет. Основные причины остановки листа:

- `no_meaningful_splits`: исследованные варианты не дают достаточного
  геометрического улучшения либо оставляют слишком маленькие/тонкие части;
- `no_feasible_connections`: геометрически полезные варианты есть, но
  исследованные крепления, защитные зоны или последовательности не подходят;
- `technical_limit_reached`: вычислительный лимит не позволил закончить поиск.

Дополнительно сохраняется `decomposition_complete_within_search`. Значение
`false` не делает уже проверенную сборку геометрически невалидной, но запрещает
считать её декомпозицию завершённой даже в исследованном семействе кандидатов.
Ни при каком статусе не заявляется перебор всех возможных плоскостей.

## Стыки и выбор креплений

`cadgen/joint_design.py` строит варианты на реальной общей контактной области.
`cadgen/assembly_planning.py` проверяет граф всех соприкосновений и связность
выбранного набора соединений. Принятые рекурсивные соединения образуют дерево;
дополнительные геометрические касания сохраняются в графе без обязательного
добавления ещё одного крепежа.

Профили задаются единожды в `generirovanie_pazov/`. Автоматический режим
переиспользует прежние проверенные построители с контактной областью в качестве
ограничения размера/положения. Предпочтения:

- длинная площадка — `dovetail`/`t` с продольным подведением;
- заметная доля криволинейных поверхностей — `round`;
- узкая направляющая — `v`/`trapezoid`;
- общий массивный стык — `rectangular`.

Если предпочтительный профиль не проходит точные проверки, пробуются другие.
Зазор — нормальное смещение общего профиля, по умолчанию 0.2 мм. Для `round`
радиальный зазор 0.2 мм соответствует диаметральному 0.4 мм. Допустимо
`0 <= clearance < 1` мм. T-паз и ласточкин хвост принимаются только при
проверенном продольном пути и открытых торцах.

Для широкой почти равносторонней плоской площадки болтовое соединение получает
более высокий приоритет. Оси выбираются из реальных контактных областей;
проверяются материальная колонна, соосные сквозные отверстия, наружные опорные
площадки и доступ. Количество болтов зависит от протяжённости площадки и
выполнимого размещения с расстоянием между креплениями; оно не одинаково для
каждого случая. Используются прежние `Bolty`, `Gaiki`, `Otverstiya`.

Комбинированное соединение рассматривается для продольной направляющей, когда
отдельно от неё помещается доступный болт как условный ограничитель скольжения.
Болт не добавляется к каждому пазу. Защитные зоны паза и болта должны быть
разделены. Все варианты ранжируются после локальных геометрических проверок;
пересечение будущих ступенчатых переходов защитной зоной понижает приоритет.

Несколько соединений одного компонента учитываются совместно. После применения
всех модификаций проверяются валидность и объёмы, все пары основных деталей
и крепежа, а также отличие объединения основных частей от исходника.
Объём болтов/гаек не включается в исходное тело. Разрешены только рассчитанные
пустоты пазовых зазоров и технологических отверстий.

**Резьбы нет.** Не рассчитываются прочность, трение, преднатяг или механическое
удержание. Болт и гайка — гладкие геометрические элементы.

## Полная последовательность сборки

Поиск идёт через обратное разъединение всей конструкции с возвратами:

1. Кандидат на удаление проверяется против **всех** оставшихся компонентов.
2. Учитываются направления всех ещё активных пазов компонента.
3. Основная часть не удаляется, пока установлен относящийся к ней крепёж.
4. Гайка удаляется перед соответствующим болтом.
5. После неудачи проверяются другие компоненты/допустимые направления.

Обратный порядок даёт последовательность сборки: база, подведение основных
компонентов, доступные болты и гайки. Каждый шаг содержит все ранее установленные
элементы, направление, начальный сдвиг, конечное положение и отсчёты траектории
в системе исходной модели. Заблокированная конструкция отклоняется.

Проверка траектории конечная, дискретная. Она не доказывает отсутствие
столкновений между отсчётами, а поиск выбранных прямых движений не является
исчерпывающим поиском произвольных пространственных траекторий.

## Параметры качества и технические лимиты

Качество: `--min-component-size 6`, `--min-component-volume 300`,
`--min-split-score 0.8`, `--min-simplicity-gain 0.08`, `--min-wall 2`,
`--clearance 0.2`, `--volume-tolerance 1e-5`. Единицы: мм, мм³ для объёмов.
Веса доступны как `--neck-weight`, `--transition-weight`, `--simplicity-weight`,
`--imbalance-weight`. Локальные проверки материала не сертифицируют глобальную
минимальную толщину каждой стенки модели.

Технические пределы:

- `--max-cut-candidates 160` на анализ компонента;
- `--max-recursion-depth 12`, без целевого количества листьев;
- `--max-connection-trials 12` геометрических кандидатов на один проход;
- `--max-sequence-states 256` состояний поиска порядка сборки;
- `--cad-operation-budget 5000` учётных единиц анализа сечений/разрезов;
- `--max-attempts 8` исходников на запрошенную сборку;
- `--feature-attempts 8` позиций локального крепления;
- `--path-steps 16` базовых интервалов плюс близкие к контакту отсчёты.

Счётчик `budget.cad_operations` — приближённый бюджет анализа: одно сечение
стоит одну единицу, рассмотрение разреза — четыре. Низкоуровневые вызовы OCC
внутри функций и проверки креплений не подсчитываются поштучно; они ограничены
отдельными пределами вариантов/состояний. Лимит времени одного вызова OCC
не реализован. Эти пределы не являются геометрическими условиями окончания.

## Файлы и демонстрации

В каждой успешной сборке:

```text
original.step / original.stl / original.py
split_exploded.step / split_exploded.stl
parts_exploded.stl
assembly.step / assembly.stl
exploded.step
split_part_1.step / split_part_1.stl / ...  # до креплений
part_1.step / part_1.stl / ...              # после креплений
bolt_1.step / bolt_1.stl / ...              # если есть
nut_1.step / nut_1.stl / ...                # если есть
metadata.json
```

Каждый компонент имеет отдельные STEP/STL и размещение. Разобранные виды
раскладываются на непересекающиеся места с видимыми промежутками, только
перемещениями, без масштабирования. Исходные части и части после креплений
сохранены раздельно. После экспорта STEP повторно читаются, STL проверяются
на читаемость, конечные координаты, непустую сетку и положительный объём.
При необходимости уменьшается только плотность STL-сетки; STEP не меняется.
Каждый STL ограничен 10 MB для просмотра на GitHub.

Обычные результаты находятся в исключённом из Git `generations/assemblies/`.
`--examples` копирует не более десяти реальных успешных результатов в отдельный
новый каталог и создаёт README с относительными ссылками на все четыре вида.
Публикация и коммит не выполняются автоматически.

Подготовленная демонстрационная серия: [examples/assemblies/README.md](examples/assemblies/README.md).
Статистика исходников и отказов — `examples/assemblies/experiment.json`;
параметры, разрезы, стыки, причины остановки и полный порядок — `metadata.json`
каждой модели. Seed серии и seed отдельного успешного исходника различаются
после неудачных попыток. Для воспроизведения используйте `request`, `settings`
и `decomposition_settings` вместе с соответствующим seed.

## Проверки и ограничения

```bash
python -m unittest discover -s test -p 'test_*.py' -v
python test/validate_auto_examples.py --folder examples/assemblies
```

Новый `test/test_auto_decomposition.py` проверяет перемычки, ступени, отсутствие
ненужного разрезания коробки, рекурсивное восстановление исходника, повороты,
лимиты, невыполнимые крепления, связность реального графа, несколько стыков,
все профили, геометрический выбор крепежа, комбинированное соединение,
полный порядок, заблокированную полость, четыре представления и настоящий
полный сценарий CADGen → декомпозиция → STEP/STL → демонстрационный каталог.
Прежние тесты выполняются той же командой.

Выполненный эксперимент, таблица десяти моделей, отказы и границы проверенных
возможностей: [AUTO_EXPERIMENT.md](AUTO_EXPERIMENT.md). Пройдены 44 теста и
независимый контроль десяти экспортированных моделей. Валидатор повторяет
исходную программу CADGen и восстанавливает ожидаемые детали по параметрам
соединений для прямого сравнения B-Rep; численные интегралы объёма учитывает
отдельно. Запускайте его только для доверенных локальных примеров.

Алгоритм эвристический, с жадным выбором разрезов и ограниченной заменой
родительских креплений. Он не гарантирует глобально оптимальную или единственную
декомпозицию. Исследуются три семейства направлений и выбранные уровни; гладкие
переходы, сложные свободные поверхности и другие траектории могут быть пропущены.
`no_meaningful_splits` относится к этим критериям и вариантам, а не ко всем
мысленно возможным разрезам. Условия материала локальные, настоящая прочность
и производственная технологичность не доказаны.
