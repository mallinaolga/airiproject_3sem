# Генерация и поиск соединений

Все команды ниже выполняются в PowerShell из папки проекта:

```powershell
cd "C:\Users\User\airiproject_3sem\cadgen-students 3"
```

Используется уже установленное окружение `.venv-win` с Python 3.11.
Повторная установка проекта не требуется для editable-установки (`pip install -e .`).

## Что теперь считается соединением

Проверка `python -m cadgen.assembly_search` непосредственно читает STEP-файлы
выбранного набора. Старые `connection_features*.json` и `assembly_alignment.json`
ей не нужны.

Достаточно одного из трёх видов геометрического соответствия:

1. **Контакт по двум направлениям.** Например, куб внутри уголка или брусок
   у двух стенок квадратного отверстия. У каждой контактной площадки должна
   быть достаточная площадь; направления нормалей различаются минимум на 20°.
   Допускается небольшой зазор в пределах `--contact-tolerance` (по умолчанию 0.1).
2. **Криволинейная выемка.** Для овальных и сферических поверхностей строятся
   гипотезы совмещения с вогнутой поверхностью. На реальных поверхностях
   проверяются несколько близких точек с противоположными нормалями,
   распределённых по разным направлениям. Это дискретная оценка контакта,
   а не точное вычисление площади криволинейного сопряжения.
3. **Вставка цилиндра в отверстие.** Проверяются соосность, радиальный зазор и
   глубина взаимного перекрытия по оси (не менее `--min-engagement`, по умолчанию 1).
   Полный контакт не обязателен; свободная вставка с зазором допустима.

Во всех случаях объёмное пересечение материала запрещено. Численный допуск
`--volume-tolerance` (по умолчанию 1e-5) относится к объёму пересечения, а не к зазору.
Одиночное касание плоскости, ребра или точки без описанного соответствия
не считается найденным соединением. Детали не масштабируются и не деформируются.
Размеры и площади задаются в единицах импортированного STEP; модели генератора
обычно интерпретируются в мм.

Из найденного положения проверяется прямолинейное удаление детали до полностью
раздельного положения. Обратный путь — подведение к сборке. Проверяются конечное
положение и промежуточные отсчёты, в том числе близкие к контакту. Это **не доказательство
непрерывного пути**: тонкое препятствие между отсчётами может быть пропущено.
Фиксация, трение, нагрузки и производственные допуски не рассчитываются.

Поиск ограничен числом признаков и поз. Сейчас гипотезы строятся по прямым
внутренним/наружным углам, полным цилиндрическим поверхностям и распознанным
эллипсоидальным/сферическим участкам. Сложные свободные поверхности, деформация,
резьба, произвольные траектории и все возможные ориентации не перебираются.
`not_found` означает «решение не найдено данным поиском», а не «сборка невозможна».

## Сначала посмотреть уголок и выемку

```powershell
.\.venv-win\Scripts\python.exe test/connection_examples.py
```

Появится новая папка `test/contact_examples_...`.
Открой `corner_cube/connections/assemblies/pair_000_001.stl` и

В этих примерах вторые детали изначально перемещены и повёрнуты:

## Сгенерировать 1, 10 или 100 деталей

Выбери нужную команду. Имена папок новые, чтобы не смешивать наборы.
При повторной генерации используй новое имя, например `run_10_b`:
сам генератор может перезаписывать прежние образцы.

```powershell
.\.venv-win\Scripts\cadgen.exe gen --output generations/run_1 --n-train-samples 1 --n-val-samples 0 --n-folders 1 --max-workers 1 --log-exceptions
```

```powershell
.\.venv-win\Scripts\cadgen.exe gen --output generations/run_10 --n-train-samples 10 --n-val-samples 0 --n-folders 1 --max-workers 1 --log-exceptions
```

```powershell
.\.venv-win\Scripts\cadgen.exe gen --output generations/run_100 --n-train-samples 100 --n-val-samples 0 --n-folders 1 --max-workers 1 --log-exceptions
```

Генератор создаёт случайные детали. Наличие подходящих соединений не гарантируется.

## Проверить набор

```powershell
.\.venv-win\Scripts\python.exe -m cadgen.assembly_search --folder generations/run_1/train
```

У одной детали нет пары: будет отчёт с нулём сравнений. Для соединения с другой
моделью помести STEP-файлы обеих деталей в отдельную общую папку и укажи её.

```powershell
.\.venv-win\Scripts\python.exe -m cadgen.assembly_search --folder generations/run_10/train
```

```powershell
.\.venv-win\Scripts\python.exe -m cadgen.assembly_search --folder generations/run_100/train
```

Для 10 деталей это 45 уникальных пар, для 100 — 4950. При поиске рассматриваются
обе роли деталей: какая содержит отверстие/выемку и какая вставляется.
Каждая пара проверяется до первого подходящего результата или исчерпания
лимита поз (32 по умолчанию). Сотня сложных деталей может потребовать
значительного времени; результаты завершённых пар сохраняются постепенно.
`Ctrl+C` останавливает поиск и оставляет готовую часть отчёта.

Для предварительного прогона первых 100 пар:

```powershell
.\.venv-win\Scripts\python.exe -m cadgen.assembly_search --folder generations/run_100/train --max-pairs 100
```

Более широкий поиск и более частая проверка пути:

```powershell
.\.venv-win\Scripts\python.exe -m cadgen.assembly_search --folder generations/run_10/train --max-poses 128 --path-steps 40
```

## Где результат

Внутри указанной папки создаётся новая `connections_ДАТА_ВРЕМЯ`:

```text
connections_.../
  report.json
  assemblies/
    pair_000_009.stl
    pair_000_009.step
    ...
```

По умолчанию экспортируется максимум 100 сборок, но проверка всех пар продолжается.
Для экспорта всех найденных сборок из 100 деталей добавь `--max-exports 4950`.
Номер в имени сборки — индекс файла в списке `parts` отчёта; это не обязательно
номер детали из генератора. Полные пути к исходным моделям находятся в каждой паре.

Состояния пар в `report.json`:

- `connection_found`: геометрия подходит, на проверенных отсчётах пути
  столкновений не найдено; STL/STEP экспортируются с учётом лимита;
- `pose_only`: подходящее конечное положение есть, проверенный путь не найден;
- `not_found`: подходящий вариант не найден в пределах поиска;
- `error`: проверка не смогла оценить позы; подробности в `errors`.

Отчёт также содержит ошибки чтения, предупреждения распознавания, поворот,
перемещение, причины принятия, контактные площадки либо зазор/глубину вставки,
параметры и результат проверки пути. Ошибки экспорта указываются отдельно.

Открывай STL через **Open in Viewer** в VS Code. STEP содержит две отдельные
детали с разными цветами; обычный STL цвета не сохраняет.

## Проверки реализации

```powershell
.\.venv-win\Scripts\python.exe -m unittest discover -s test -p test_connections.py -v
```

Проверяются уголок и куб, произвольный поворот и обратный порядок деталей,
овал в неглубокой выемке, квадратное отверстие, цилиндр с зазором,
неподходящий цилиндр, столкновения, одиночные касания, набор из одной детали,
чтение STEP/STP и экспорт сборки.

Старый `test/test.py` остаётся специализированным примером генерации колец
и брусков с собственной проверкой прямой вставки. Для новой общей проверки
используй именно `cadgen.assembly_search`.
