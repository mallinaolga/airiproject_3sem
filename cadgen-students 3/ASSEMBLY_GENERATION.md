# Генерация сборок из одной модели

Двухкомпонентный режим ниже сохранён. Новый рекурсивный режим
`--decomposition auto --connection auto` описан в [AUTO_DECOMPOSITION.md](AUTO_DECOMPOSITION.md).

Новый конвейер работает отдельно от исходного CADGen. Он получает одно
цельное тело, разделяет его плоскостью, создаёт согласованное соединение и
сохраняет проверенную сборку. Старый перебор независимых пар не используется.
Ядро CADGen и определения шести профилей не изменены.

## Быстрый запуск

Команды выполняются из `cadgen-students 3` с установленными зависимостями
проекта. В текущей облачной среде:

```bash
cd "/workspace/airiproject_3sem/cadgen-students 3"
source /workspace/.venvs/airi/bin/activate
```

На новой машине достаточно обычной установки проекта в виртуальное окружение:

```bash
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# PowerShell: .\.venv\Scripts\Activate.ps1
python -m pip install -e .
```

Одно прямоугольное соединение, один болт с гайкой, затем случайная серия:

```bash
python -m cadgen.assembly_generator --count 1 --connection groove --seed 42
python -m cadgen.assembly_generator --count 1 --connection bolted --seed 42
python -m cadgen.assembly_generator --count 10 --connection random --seed 42
```

По умолчанию источник — процедурная геометрия существующего `CADFactory`:
случайные эскизы и от одной до трёх запрошенных операций экструзии. CADGen
может отклонить отдельные операции; их фактическое число записывается в
метаданные. Размер мира выбирается в диапазоне 65–100 мм. Готовые шаблоны
независимых деталей не подставляются в качестве скрытого запасного варианта.

Для отладки можно явно выбрать случайный параллелепипед:

```bash
python -m cadgen.assembly_generator --source box --connection groove --count 1 --seed 42
```

Существующая Python-конфигурация CADGen, экспортирующая `cad_factory`,
подключается явно, например:

```bash
python -m cadgen.assembly_generator --connection groove --cad-config configs/operations/extrude.py --seed 42
```

Используйте локальные доверенные конфигурации без закрытых зависимостей.
Сложная конфигурация не гарантирует размещение крепления; сохраняются причины
отклонений, а число попыток ограничено. Поддержка всех старых конфигураций
CADGen этим конвейером не заявляется.

## Что происходит с геометрией

1. Проверяется валидность B-Rep, одно Solid и положительный объём источника.
   Сохраняются исходная модель, параметры CADGen и исполняемый `original.py`.
2. Алгоритм рассматривает нормали реальных плоских граней и мировые оси в
   случайном порядке. В пазовом режиме после них возможны косые разрезы.
   Положение плоскости случайно смещается около центра масс. Одна фиксированная
   плоскость не используется для всех моделей. Нормали граней позволяют
   находить плоские опорные площадки и у повёрнутых моделей.
3. Модель жёстко переводится во вспомогательную ортонормированную систему,
   где разрез — Z=0. Пересечение с полупространствами создаёт две части.
   Каждая должна быть одним валидным Solid, иметь минимум 15% объёма источника
   и достаточную глубину. Их объединение должно восстанавливать исходник
   по симметрической разности объёмов в пределах `volume_tolerance`.
4. Создаётся соединение, проверяются модифицированные части, их объёмные
   пересечения, технологические пустоты и последовательность вставки.
5. Компоненты экспортируются отдельно и размещаются через `cadquery.Assembly`.
   STEP повторно читается: проверяются число отдельных Solid, их объёмы и
   положения относительно геометрии, уже прошедшей проверки.

Оригинальное тело не модифицируется. Все операции вырезания и добавления
относятся к новым компонентам. Масштабирования исходной модели для подгонки
соединения нет.

## Пазы и выступы

Все шесть профилей используют существующие `Profile`, `sample_profile()` и
`profile_prism()` из `generirovanie_pazov/generate_grooves.py`:

| `--profile` | Подведение | Геометрия паза |
|---|---|---|
| `rectangular` (по умолчанию) | Перпендикулярно разрезу | Закрытый карман |
| `v` | Перпендикулярно разрезу | Закрытый карман |
| `trapezoid` | Перпендикулярно разрезу | Закрытый карман |
| `round` | Перпендикулярно разрезу | Закрытый карман |
| `dovetail` | Продольное скольжение вдоль паза | Открытые торцы |
| `t` | Продольное скольжение вдоль паза | Открытые торцы |

```bash
python -m cadgen.assembly_generator --connection groove --profile dovetail --seed 42 --count 1
python -m cadgen.assembly_generator --connection groove --profile random --seed 42 --count 10
```

Сначала выбирается одна общая геометрия профиля. Объём выступа переносится из
нижней половины в верхнюю; в нижней вырезается соответствующий паз. Это две
половины одного исходного тела, а не независимо сгенерированные детали.

Паз строится истинным плоским смещением границы профиля на `--clearance`.
По умолчанию это **0.2 мм по нормали к сопрягаемой поверхности**. Фактические
расстояния на внутренних участках поверхностей профиля проверяются и
записываются в `measured_profile_surface_gaps`. Для круглого профиля это
радиальный зазор 0.2 мм, диаметральный — 0.4 мм. Закрытый карман также
удлиняется на этот зазор с каждого торца. Допускается `0 <= clearance < 1` мм.

Проверяются материал вокруг центрального участка паза, толщина его дна и
основание выступа. У `dovetail` и `t` инструмент проходит через всю модель
в продольном направлении; выступ обрезается исходным объёмом, поэтому не
добавляет материал снаружи исходной формы. Пригодность продольного скольжения
обязательно проверяется. При заблокированном пути вариант отклоняется.

Параметр `--min-wall` (2 мм по умолчанию) задаёт локальный запас материала
вокруг места крепления. Это проверка выбранных оболочек/колонн и связности
результата, а не сертификат минимальной толщины каждой стенки всей модели.

## Болтовой режим

Через две половины проводится одна согласованная ось сквозных отверстий.
Алгоритм ищет внутри исходного тела полную материальную колонну с запасом
под головку и гайку. Верхняя и нижняя опорные площадки должны быть плоскими
и доступными снаружи. Если подходящей колонны нет, проверяется другой
разрез/место, затем при необходимости другая исходная модель.

Используется существующий `Bolty.build_bolt(BoltSpec(...))`, а также добавленные
явные параметры `Gaiki.NutSpec` / `Gaiki.build_nut()`. Общий инструмент отверстия
`Otverstiya.through_hole_cutter()` применяется к обеим половинам. Старые
случайные генераторы гаек и пластин сохраняют интерфейсы и проходят прежние
тесты; болты и исходные профили не изменены.

Текущий вариант использует один болт с шестигранной головкой, гладкий стержень
диаметром 4, 5 или 6 мм и одну шестигранную гайку. Головка шире стержня на
4 мм, высота головки и гайки — 4 мм. Длина стержня равна толщине модели вдоль
оси плюс высота гайки и 2 мм выступания. Эти размеры рассчитываются совместно,
а не берутся из независимых случайных генераций.

`--clearance 0.2` здесь означает **радиальный** зазор; отверстие и отверстие
гайки на 0.4 мм больше стержня по диаметру. Проверяются соосность, сквозное
удаление материала в обеих половинах, длина стержня, площади опирания головки
и гайки, отсутствие пересечений всех пар компонентов. Последовательность:
подвести основные части, вставить болт, затем надеть гайку с противоположной
стороны. Для каждого движения сохраняется отдельная проверенная по отсчётам
траектория.

**Настоящей резьбы нет.** Моделируется геометрически совместимый гладкий
крепёж. Резьбовое удержание, трение и механическая фиксация не подтверждаются.

## Проверки, попытки и воспроизводимость

Допуск булевых объёмных операций по умолчанию — `1e-5` мм³. Он отделён от
физического зазора в миллиметрах. Сравнивается геометрия объединения основных
деталей с оригиналом: разрешены только рассчитанные пустоты от зазора или
сквозного канала. Посторонние добавления/потери материала отклоняются.

Прямолинейные пути проверяются в конечном числе положений, включая конечное,
раздельное начальное и дополнительные близкие к контакту отсчёты. В отчёте
есть направления, расстояния и число положений. Это **не доказательство**
отсутствия столкновения между отсчётами. Разобранные положения служат для
просмотра; они отдельно от проверенных последовательностей сборки.

Лимиты по умолчанию:

- `--max-attempts 8`: исходных моделей на одну запрошенную сборку;
- `--plane-attempts 9`: плоскостей на одну модель;
- `--feature-attempts 8`: мест крепления на одну плоскость;
- `--path-steps 16`: базовых интервалов прямолинейной траектории плюс дополнительные отсчёты.

При увеличении сложности модели стоимость одной B-Rep-операции также растёт;
эти лимиты ограничивают число вариантов, но не задают тайм-аут операции OCC.

`--count` — требуемое число **успешных сборок**. Неудачные исходники,
разрезы и экспорты в это число не входят. После исчерпания попыток сохраняется
`manifest.json` с фактическим числом успехов, причинами отказа и статусом
`incomplete`; CLI возвращает код 1. Неверные параметры дают код 2, выполнение
запрошенного числа — код 0. Отсутствие решения в пределах лимитов не означает
доказанную невозможность сборки.

`--seed` фиксирует геометрию и последовательность попыток в том же программном
окружении. В манифесте хранится seed серии, в каждой `metadata.json` — seed
конкретного успешного исходника. Для воспроизведения отдельной модели берите
её seed и исходные режим/профиль из `metadata.request`, а также настройки из
`metadata.settings`. Для запроса `random` нужно повторить именно `random`,
поскольку случайный выбор тоже расходует seed-последовательность.
Python/NumPy RNG вызывающего кода
восстанавливаются после обращения к CADGen. Побайтовая идентичность STEP и
воспроизводимость между версиями OCC не гарантируются.

## Выходные файлы и просмотр

По умолчанию создаётся новый каталог
`generations/assemblies/run_ДАТА_ВРЕМЯ`. Можно задать новый `--output`;
существующая папка никогда не перезаписывается. Стандартный каталог исключён
из Git. Не добавляйте экспортированные модели в репозиторий вручную.

```text
run_.../
  manifest.json
  assembly_0001_attempt_01_slot_0001/
    original.step / original.stl / original.py
    part_1.step / part_1.stl
    part_2.step / part_2.stl
    bolt_1.step / bolt_1.stl      # только bolted
    nut_1.step / nut_1.stl        # только bolted
    assembly.step / assembly.stl
    exploded.step / exploded.stl
    metadata.json
```

Компонентные STEP/STL имеют локальные координаты около собственного центра.
Матрица поворота и перенос в `metadata.components` восстанавливают их положение
в сборке и разобранном представлении. В STEP-сборке детали сохраняются
отдельными Solid; STL содержит их совместную сетку без цветов.

`metadata.json` содержит источник/параметры CADGen, seed, плоскость разреза,
общий профиль либо размеры крепежа, зазоры, положения/происхождение компонентов,
результаты проверок и отклонённые кандидаты. Успех записывается только после
повторного чтения экспортированной STEP-сборки. Сбой экспорта оставляет
`success: false` и `status: export_failed` в частичном каталоге.

Открывайте `original.step`, `assembly.step` и `exploded.step` в CAD-просмотрщике;
STL можно открыть через Open in Viewer в VS Code.

## Ограничения и следующие шаги

- Сейчас только две основные части, один паз/выступ либо один гладкий болт
  с гайкой. Комбинированное крепление и три и более основные части не реализованы.
- Не каждая модель CADGen подходит: тонкие стенки, пустоты, сложные формы или
  отсутствие внешних плоских площадок могут привести к исчерпанию попыток.
- Расположение креплений выбирается ограниченными пробами и локальными
  проверками материала; глобальная минимальная толщина, прочность и
  технологичность изготовления не сертифицируются.
- Проверяются только выбранные прямолинейные траектории. Непрерывная проверка,
  сложные движения, резьба и механическое удержание требуют отдельной работы.
- Перспективы: рекурсивное разделение, несколько креплений, сочетание пазов
  с болтами, расширенный поиск опорных площадок и адаптивная проверка пути.
